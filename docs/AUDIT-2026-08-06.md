## Fixed In This Release

| Issue | Root Cause | Fix | Rollback |
| --- | --- | --- | --- |
| Google sitemap submissions could occur daily | Daily sitemap Cron used `GOOGLE_SEARCH_CONSOLE_ENABLED` to submit as part of refresh | Daily `/api/cron/sitemap` now refreshes only. New `/api/cron/google-sitemap-submit` submits once every three calendar days at `10 18 */3 * *` UTC. | Restore `vercel.json` and `app/api/cron/sitemap/route.js` from the backup snapshot. |
| Legacy product migration could overwrite CMS products annually | `/api/cron/sync-legacy-products` performs a full product replacement and was scheduled every Jan 1 | Removed the automatic schedule; the existing secret-protected recovery endpoint remains available for deliberate recovery only. | Restore the removed Cron block in `vercel.json`. |
| Google duplicate submit path in legacy sync | Legacy product sync called `refreshSitemap({ submit: true })` | Changed to refresh sitemap only. | Restore the backed-up route file. |

## Known Limits And Follow-Up Risks

1. `npm audit --omit=dev` reported three high-severity production dependency findings through `next@16.2.10` (`next`, transitive `postcss`, `sharp`). Upgrade to `next@16.2.11` or newer is available, but the package download timed out after two minutes in this environment and no manifest/lockfile change was made. This remains open, high priority.
2. The Vercel runtime-log API returned `ExceedsBillingLimitError`; the aggregate query also timed out. Therefore individual production Cron execution logs, CPU/memory/disk metrics, and serverless error history could not be independently read from this session.
3. Vercel environment-variable values and direct Neon SQL access are not exposed to this session. Production persistence is confirmed by `/api/health` and real content reads, but table definitions, indexes, database roles, write permissions and direct query plans could not be inspected without database/variable access.
4. Four older visible News records in the first 100 API results do not include source or explicit SEO fields. The public renderer supplies fallbacks, so the checked public pages remain valid; direct database repair requires authenticated CMS or Neon access and was not attempted to avoid altering live records blindly.
5. Google service-account credentials and the next actual three-day submission result cannot be invoked safely without `CRON_SECRET` or Vercel logs. The route is compiled, protected, scheduled in `vercel.json`, and records its result through the existing sitemap-run persistent log path when executed.
